# 电商智能客服 RAG 知识库系统 PRD (v1.2)

## 1. 业务背景与问题痛点
当前电商平台大促期间人工客服接待成本高，传统规则型 Chatbot 无法理解长尾复杂售后问题，且无法直接关联订单数据与退换货细则，用户满意度持续下滑。

## 2. 产品目标与核心指标
* **降低人工分流率**：将售前咨询与退换货规则咨询的人工转接率降低 40%。
* **首响与解决率**：首字生成延迟（TTFT）控制在 800ms 内，单轮问题解决率达 75%。
* **知识召回准确率**：RAG 检索 Top-3 准确率 >= 88%。

## 3. 核心功能与技术方案设计

### 3.1 文档入库与切片规则
* **支持格式**：店铺售后政策（PDF）、商品详情与规约（Word/MD）。
* **分块策略**：按语义段落进行切块，Chunk Size 设置为 600 tokens，Overlap 为 120 tokens。
* **元数据标注**：必须携带店铺 ID、类目 ID、文档发布时间、生效状态（有效/作废）。

### 3.2 混合检索链路 (Hybrid Search)
1. **意图初筛**：通过小型分类模型识别是否为法规/政策咨询。
2. **两路召回**：
   * 向量检索：使用 OpenAI text-embedding-3-small 向量表征。
   * 倒排索引：BM25 关键词匹配，强化商品型号与专有名词召回。
3. **重排层 (Reranker)**：采用 BGE-Reranker-Large，对两路召回的 20 条候选分块计算语义相关度得分，过滤掉得分低于 0.4 的片段，取 Top-3 送入 LLM。

### 3.3 兜底与降级逻辑 (Fallback)
* 若检索重排后的最高置信度得分 < 0.35，禁止大模型强行回答，统一输出：“很抱歉，当前政策中暂未检索到该规则，正在为您转接人工客服”。

## 4. 边界异常与风控
* 涉及退款金额计算、价格争议的咨询，强制调用底层结算 API 查询真实订单，禁止大模型根据上下文虚构优惠金额。
